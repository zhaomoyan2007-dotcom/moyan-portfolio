# 墨岩 · Photography & Cinematography

原生静态作品网站，沿用已确认的大图、黑白排版、中英切换和摄影／短片分区。第一版以100～500张照片或剧照为目标，先保留6张作者授权的测试照片，不为测试图补写项目名称或介绍。

## 本机运行

需要Node.js 22或更新版本。首次运行：

```sh
npm ci
npm run dev
```

- 网站：<http://localhost:4319/>
- 作品管理：<http://localhost:4319/admin/>
- 本地后台点击“登录”进入本机编辑；不使用云端账号，也不证明线上认证已完成。
- 本地服务和内容代理仅绑定127.0.0.1。端口4319或8081被占用时拒绝启动，避免连错工程。
- 后台可批量上传网页副本、拖动排序、改封面、维护双语文字和精选。保存后刷新网站查看。
- 本地模式不支持GitHub的草稿审核工作流，保存直接影响本机页面。线上模式另见下文。

## 内容组织

- `content/site.json`：首页开场图、精选图序列、署名、双语简介和联系方式。
- `content/projects/*.json`：项目分类、固定地址、双语标题与文字、封面、图序、精选及公开状态。
- `public/`：前台页面、样式、图片及Decap后台入口。
- `lib/`：内容校验、媒体处理、CMS配置、OAuth和本地开发工具。
- `scripts/`：构建、本地服务与检查。
- `api/`：线上GitHub OAuth登录与回调。
- `tests/`：内容、草稿隔离、上传校验、端口隔离和OAuth边界测试。

项目创建后固定`id`，分享地址为`/#project/项目id`。更改标题不改变地址。项目标为`draft`后，在下一次成功发布中从公开目录和详情中撤下；图片文件不因此自动删除。

## 线上后台与发布

使用Decap CMS + GitHub editorial workflow。Cloudinary管理线上图片；GitHub保存项目文字和图片引用；Vercel只导出正式分支已发布的内容。

1. 后台中编辑项目，先保存为工作流草稿，在右侧预览。
2. 确认项目的“公开状态”为“公开展示”，再使用工作流发布动作合并到主分支。
3. 等Vercel构建成功后检查正式网址；保存或合并成功不等于部署已成功。
4. 若要撤下，编辑为“草稿／已撤下”，同样发布该变更并等待构建。

CMS的`cms/`草稿分支不允许生成公开Vercel预览，内部预览可用。公开GitHub仓库中的分支和素材仍可被外部读取，因此不应存放保密素材。正式方案不是私人网盘。

尚未配置线上账号时，`/admin/`显示接入说明，不提供虚假的可用登录。配置步骤在[DEPLOYMENT.md](DEPLOYMENT.md)。

## 验证与构建

```sh
npm test
npm run check
npm run build
npm run check:deploy
```

构建输出`dist/`。它只包含已发布项目，不包括原始`content/`目录、测试脚本、环境变量或本地上传接口。内容校验失败时停止发布。

Decap CMS固定为3.17.1。首次构建通过npm获取精确版本包并校验SHA-512，随后将运行资源放在本地`public/admin/vendor/`，不依赖浏览器从第三方脚本CDN加载。生成资源、缓存和`node_modules`不提交。许可证记录见[THIRD_PARTY.md](THIRD_PARTY.md)。

## 上传前自动压缩

线上图片窗口新增“选择照片并自动压缩”：保留电脑原文件，最长边3000像素、WebP、目标4MB以内，支持逐张进度和失败重试。已有Cloudinary图片库选择保留。原图片库的Upload按钮不经过压缩，新上传大图请使用新入口。

需要在Vercel新增服务端变量CLOUDINARY_API_SECRET，并重新部署、重新登录后台。格式、大小与授权边界见DEPLOYMENT；新增流程的真实上传需完成这项配置后验收。

## 分类照片流

首页摄影区分为纪实、当代与情绪、人像、体育、航拍、自然风光。原8张精选已按作者要求撤下，保留空栏目；云端文件未删除。

在后台“作品项目／首页展示”新建项目：固定地址自动生成；选择类别，人像另选环境或棚拍，添加照片并拖动排序，开启“加入首页摄影照片流”，选择公开展示后完成工作流发布。纪实、当代与情绪、体育每项目一排标准横向照片流，不显示项目名或简介。体育不再区分篮球／足球，也不限制三张或每项运动一个项目；已有分组字段兼容保留但不影响布局。航拍和自然风光使用居中最大960px、电脑三列、间距14px的原比例无底板网格，手机520px以下两列、间距10px；保留图片放大与键盘焦点。后台对应项目预览使用同样的网格／横向照片流规则。

图片可点开放大，组内按钮、方向键及触屏滑动切换，Esc关闭并返回原图。没有内容时仅显示栏目占位结构。

首页首图按图片自身比例显示，完整保留构图，最大宽度1440像素；首图与精选入口封面均按自身比例完整显示，四周使用宽范围、多段透明渐变融入黑底。简介自然排在下方，不再通过固定画框裁切或滚动位移首图。精选入口封面独立于下方分类照片流，即使栏目为空也显示后台上传的封面；两个入口共用这张封面。


后续视觉调整默认在本地预览集中修改、确认后一并发布；不把每次试版上传到 GitHub。启动 `npm run dev` 后，本机预览为 http://localhost:4319/，现有本地图文后台为 http://localhost:4319/admin/。线上后台保存发布仍会触发线上更新，试版时请使用本地入口。布局由工程维护，图文由已有后台维护。


当前本地版恢复个人阐述下的简单双按钮：左为静态影像、右为短片创作，不显示精选标题及英文眉题；保留向下箭头和后续剧场照片。顶部精选导航定位到双按钮，箭头定位到剧场照片。

## 首页短片创作（本地待验收）

首页直接按项目展示：名称与时间 → 独立首图 → 静态切片图组 → 个人职责 → 创作阐述。所有公开短片自动进入首页，按项目时间从新到旧，时间相同按排列顺序和固定地址稳定排列；未填时间的放在最后。摄影项目的精选和排序不变。

本地后台进入“作品项目／首页展示”创建项目，类别选“短片”。填写中英名称和“短片项目时间”（YYYY、YYYY-MM或YYYY-MM-DD；旧项目未填则沿用创作年份），单独选择“封面／短片首图”，再向“项目照片／短片其余切片”加入其他画面。切片可留空，或拖动排序；重复首图不会在小图组再次显示。个人职责和创作阐述分别维护中英内容，空字段不显示空标题。

首图最大宽960px、高度不超过屏幕72%且不超过620px；小切片电脑三列、平板和手机两列，分别限制高度240px/180px。图片按原比例完整显示，不裁切、不拉伸、不轮播。后台短片预览同时展示中英内容；摄影预览维持原流程。

本轮只实现本地，线上后台字段尚未更新。当前本地无真实短片项目，显示“短片作品整理中”；排版与不同画幅的验证采用隔离测试服务器，未向content写入测试项目。发布前仍需作者使用真实短片素材进行审美验收。

## 首页首屏与短片简介

首页背景按首屏视口铺满，文字位置独立于照片原比例；手机署名与第一段自我介绍靠近首屏下半部，后续说明与双入口自然向下延展。剧场入口图保持原布局。后台“首页与个人资料 → 网站资料 → 首页短片创作简介”可维护中英双语简介，显示于短片总标题下；留空不占位。电脑短片职责／阐述字号14px，手机保持11px，字体与灰色不变。

## 关于区域与作品导航

首页顶部直接进入静态影像和短片创作；全部作品菜单及目录筛选按作品类型和摄影子类分层。关于位于页面底部，导航支持平滑定位（减少动态效果设置除外）。后台“首页与个人资料 → 网站资料”中可改个人简介，以及“关于区域／标题、能力、合作与规划”的全部双语标题和条目；列表可增删、拖动排序，留空不显示对应条目。当前关于文案为作者允许填入的本地草稿，等待审阅后统一发布。后台同一展示模块预览中英文，正式联系方式仍由原邮箱和链接字段管理。

### 关于编辑版面（本地草稿）

新版关于按“关于我”与自由身份文本、带作品依据的实践、远期目标、与我合作排列。introBlocks 是可增删排序的双语多行文本；旧 directions 字段保留数据但不再展示。capabilities 可选关联作品项目，前台只链接当前公开作品，封面和项目名称随该作品数据更新。与我合作使用黑色胶片画幅、四周齿孔、暗红细节及装饰性 BFA 字母；导航 #collaborate 可直接定位。只有填写有效邮箱或 HTTPS 联系链接才显示联系动作。所有个人文案保持中英独立编辑；当前替换文字为作者允许的待审草稿，不代表对能力的外部认证。网站与后台共享 aboutContent 展示逻辑。
